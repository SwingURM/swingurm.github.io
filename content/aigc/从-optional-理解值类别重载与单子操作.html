从 Optional 理解值类别重载与单子操作

阅读 stl1weekend 的 Optional.hpp 时，value()、operator*()、and_then() 等函数各有四个重载，而 value_or()、or_else() 等只有两个。这里的区别不在于成员函数能写出多少种引用限定符，而在于接口需要向调用者保留哪些信息，以及这些信息会如何影响操作结果。

另一个容易让人疑惑的地方是，value() const && 返回 const T&& 时也写了 std::move(m_value)。既然值是 const，这还能移动吗？要回答这个问题，需要把“把表达式转换成右值”和“实际执行移动操作”分开看。

Optional 的存储与对象生命周期

这份 Optional<T> 可以理解为：在 Optional 自身内部始终留出一块适合存放一个 T 的存储，再单独记录那里是否有一个活着的 T。 Optional 的生命期内，这块内部存储随它存在；有值和无值的切换，通常是在这块存储中开始或结束 T 的生命期。

“内部空间一直存在”不意味着 T 自己管理的资源也一直存在。例如 Optional<std::string> 的内部空间放的是 std::string 对象，字符串内容仍可能另外动态分配；销毁字符串时，其管理的资源按字符串自身的规则释放。另外，Optional 本身也未必位于栈上：它可以是局部变量、另一个对象的成员，或通过动态分配创建。这里说的是 T 的存储嵌在 Optional 内，而不是规定外层对象在哪里分配。

与 vector、list 的存储方式比较

三者都要区分存储空间与活着的元素对象，但空间的组织方式不同。下表中的 vector 和 list 指标准容器的通常实现；节点分配和内存池的具体行为取决于分配器与实现。

类型元素存储元素构造与销毁空间何时变化
optional<T>容器对象内部容纳零个或一个 T 的空间在内部存储中构造或销毁至多一个 T内部空间随 optional 对象存在，不因 reset 或 emplace 单独分配、释放
vector<T>一段连续的元素存储，通常由分配器取得已构造元素的数量是 size；剩余容量不是现成的元素扩容可能另取更大空间并迁移元素；clear 销毁元素但保留容量
list<T>元素通常位于分别管理的链表节点中插入时构造节点中的元素，删除时销毁元素插入、删除通常伴随节点存储的取得、归还；分配器可以使用内存池

vector 与 optional 的共同点，是都可以让“有合适的存储”和“该位置有活着的元素”发生在不同时间：例如 vector 的容量大于大小时，剩余位置尚无已构造元素。区别是 vector 管理可变数量的连续位置，扩容时存储位置可能改变；optional 固定只有一个内部位置，不需要为了让 T 从空变为有值而扩容。详见 Vector 的内存分配与对象生命周期。

list 的元素则通常各自在一个节点中；节点除了元素，还需要链表链接信息。删除元素时通常也会将节点存储交还分配器，而分配器是否立即将底层内存还给系统是另一回事。节点类型和分配器的关系见 List 的节点分配器。

因此，把这个 Optional 理解为“长期保留一个位置，并反复开始和结束该位置上 T 的生命期”是合适的，但要把“长期”限定为对应的 Optional 对象自身的生命期。它描述的是 reset、emplace 等操作，不意味着每一种赋值都必须销毁后重建：例如这份教学实现的赋值采用销毁并重新构造，而标准 std::optional 在两边均有值的相应赋值情形下会对已有的 T 进行赋值。

判断重载数量的依据

分析一个成员为什么有几个重载，可以先问：这个函数把什么交给下一步操作？下一步需要区分外层对象的哪些属性？ 这里的“下一步”可能是调用者接收返回值，也可能是函数内部调用用户传入的 f。

成员交给下一步的是什么需要区分的信息本实现的重载
value、operator*内部 T 的引用调用者能否修改，以及内部值是左值还是右值四个
transform、and_then将内部 T 作为参数传给 ff 能否修改，以及按哪种值类别接收或选择重载四个
value_or新的 T有值时，通常是从内部值拷贝还是移动构造结果两个
or_else新的 Optional；空时调用无参数 f()有值时，通常是拷贝还是移动构造结果两个
operator->指向内部 T 的指针能否通过指针修改 T两个
has_value一个 bool此操作只读取状态，无须区分值类别一个 const 成员

这是理解接口设计的分析方法，并不是根据函数返回类型机械推导重载数量的语言规则：实际接口还可以选择其他语义或施加其他约束。下面分别看这些成员为什么需要、或不需要传递那些信息。

四个重载保留内部值的访问方式

Optional<T> 是一个持有或不持有 T 的包装器。value() 返回内部对象的引用，因此外层对象的两种属性都会影响返回值：const 决定是否允许通过引用修改，值类别决定内部值以左值还是右值交给调用者。

Optional<T> 的调用方式返回类型调用者获得的访问方式
非 const 左值T&可读写的左值
const 左值const T&只读的左值
非 const 右值T&&可供后续操作移动的右值
const 右值const T&&保留 const 的右值

这四个重载使包装器尽可能透明：调用者对包装器拥有什么访问方式，取得内部对象时就保留相应的访问方式。operator*() 也遵循这套设计；区别是这份实现的 value() 会在空时抛异常，而 operator*() 要求调用者先确保对象有值。

为什么其他接口只有两个重载

重载数量由函数要提供的行为决定，而不是所有成员函数都必须把四种组合逐一列出来。

value_or：按值返回，区分拷贝和移动

value_or() 返回新的 T，而不是把内部引用交给调用者。原对象有值时，主要区别是：从需要保留的值构造结果，通常拷贝；从非 const 右值构造结果，通常移动。非 const 左值可调用 const & 版本，const 右值也可调用该版本。因此不必为了返回四种引用而写四个重载。

默认值参数在调用前就会求值，所以 opt.value_or(make_default()) 即使在 opt 有值时也会调用 make_default()。如果希望只在空时才执行备用操作，可以考虑下面的 or_else()。

or_else：按值返回 Optional

or_else() 返回新的 Optional<T>。原对象有值时，const & 版本返回 *this 的副本，&& 版本从 *this 移动构造结果；原对象为空时，才调用备用函数。关键是备用函数的调用形式是 f()，没有内部值参数：有值时它不被调用，空时也没有 T 可传。因此，不需要为传给 f 的内部值区分四种访问方式，只需要为有值时按值返回区分通常的拷贝和移动路径。非 const 左值也可调用 const & 版本，const 右值则可调用 const & 版本并通常拷贝。

operator->：指针只需区分可修改性

这里返回的是指针。T* 和 const T* 表达通过该指针能否修改内部对象；指针本身并不对应 T& 与 T&& 那样的两种引用类别，所以这份实现只区分 const 与非 const。

value() 的结果是 const std::string&&。std::string 常见的移动构造函数接受 std::string&&，不能绑定到 const 对象；其拷贝构造函数接受 const std::string&，因此这个例子通过拷贝构造 s。对于只能移动、不能拷贝的类型，相应构造可能无法通过编译。

保留 const && 仍然有意义：const 和右值类别是互相独立的信息，调用者可以据此选择接受 const T&& 的重载。这里的 std::move 是为了让返回表达式具有所需的右值类别，并不承诺之后一定能移动。包装器整体的拷贝和移动可与 Function 包装器的拷贝与移动 对照；这里讨论的是访问包装器内部值时保留什么信息。

两者的区别在于传入函数的返回类型：

操作传入函数最终结果
transform(f)T → UOptional<U>
and_then(f)T → Optional<U>Optional<U>

transform 把普通的函数结果再包装为 Optional；and_then 则直接返回函数产生的 Optional。如果对返回 Optional<int> 的 parse_int 使用 transform，结果会多包一层，成为 Optional<Optional<int>>。使用 and_then 可以直接串联可能失败的步骤。

两者各有四个重载，因为它们都把内部值传给函数：左值版本分别传 T& 或 const T&，右值版本分别传 T&& 或 const T&&。这让 f 获得与调用者对应的访问方式。例如：

教学实现与标准库

这份代码展示了这些接口的主要思想，但并非 std::optional 的完整实现。尤其是它的 and_then 没有约束返回类型必须是 Optional：空分支只是默认构造推导出的返回类型，若传入函数返回 int，空分支可能得到 0，从而失去空值语义。C++23 起标准库提供的 std::optional::and_then 则要求函数的结果是 std::optional 特化。阅读实现细节时，应分别判断教学代码和标准库的约束。
